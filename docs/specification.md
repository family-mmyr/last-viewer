# 最後の視聴者 MVP 仕様

## 物語と勝利条件
AI実況者ぽこが主人公ユイを操作する。協力者タクは黒幕で、絵画の裏の「管理者 T-09／タク」を隠したい。
机の「止まった時を、4桁で」と時計の4時20分を発見すると、金庫に0420を入力してカードキーを入手する。
カードキーで出口を解錠すればクリア。絵画の記録も発見した場合は真相エンド、未発見なら脱出エンド。
金庫の番号入力はぽこが自動実行する。視聴者がユイを直接操作する機能はない。

## 状態と判断
GameStateが唯一のゲーム状態。収集物、探索履歴、実行状態、信頼度、疑惑、ヒントの残存ターンを保持する。
初期信頼度は毎回ランダム。テストでは注入する。次の行動は各対象のスコアを毎ターン再計算する。
未収集情報、手がかりによる行動可能性、探索履歴、コメント、タクの助言がスコアを変える。
信頼度が0.5超かつ疑惑0.5未満ならタクの推奨を加点し、絵画を減点する。
それ以外は助言を採用せず自分で探索する。既取得の対象は低スコアとなり、有限回で脱出に至る。
タクは未発見の記録を隠すため机・時計・出口へ誘導し、記録が発見されると助言を止める。

## 視聴者入力
日本語の対象名（机・時計・金庫・絵画・出口）を含むコメントで優先度を3ターン加算する。
「タクが怪しい」などの疑惑表現、管理者、T-09は疑惑を上げる。
自然言語全般を理解するLLMではない。ヒントは行動を可能にする条件を迂回しない。
入力は200文字、ログは80件に制限。Reactのテキスト描画を使用する。
部屋のタップまたは対象ボタンも同じコメント経路を使用する。停止中の入力は再開時に反映する。

## モジュール
- state.ts: 状態、入力解釈、行動による状態遷移
- poko.ts: PokoPolicy、スコアによる判断
- taku.ts: TakuPolicy、妨害助言
- engine.ts: tickと将来のAsyncPokoPolicy・CommentSource境界
- Room.tsx: Phaser描画とタッチ入力。ルールを変更しない
- App.tsx: React操作UI、ログ、タイマー。停止・クリア・アンマウントでタイマー解除

将来のLLM判断ではサーバーを経由し、応答の対象名と前提条件を検証し、タイムアウト時は現行方策へフォールバックする。
非同期応答にはAbortSignalとセッションIDを使い、停止・リセット前の応答を破棄する。
YouTubeはCommentSourceを実装して正規化したテキストをcommentへ渡す。認証・レート制限・配信者権限はサーバーで処理する。
現MVPにネットワーク通信、LLM、YouTube接続、保存機能は含まない。

## Safari対応方針
Vite ES2022出力のためiOS Safari 16以降を対象とする。Canvas/WebGLはPhaser AUTOで選択する。
固定論理画面720×460をScale.FITで表示。UIは850px以下で縦積みにする。
音声・外部画像・外部フォント・自動再生への依存なし。操作はpointer入力、ボタンはキーボードでも操作可能。
背景タブではブラウザによりタイマーが遅延する。経過時間ではなく実行されたターンで進行する。
